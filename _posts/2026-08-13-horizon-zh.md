<h2 class="news-title"><a href="https://a.security/blog/asecurity-zoomsday">ZOOMSDAY：Zoom 零点击漏洞可致攻击者劫持会议参与者</a><span class="score-badge score-high">10.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 13, 15:27</span></div>
<p class="news-summary">一家安全研究平台使用前沿 AI 模型发现了 Zoom 中的一个零点击远程代码执行（RCE）漏洞，该漏洞影响至 7.0.5 版本的所有原生客户端。该漏洞利用在 24 小时内用不到 20 条提示构建完成，Zoom 已在 7.1.5 和 7.0.6 版本中发布修复。 该漏洞影响 70% 的财富 100 强企业所使用的 Zoom，任何会议参与者都能静默控制 Windows、Mac、iPhone、Android 和 Linux 上所有其他参会者的设备。这一发现表明，国家级别的漏洞利用开发如今对单个研究人员而言也触手可及，从根本上改变了防御者面临的威胁格局。 该漏洞是注释功能中的一个内存损坏缺陷，具体为 CAnnoTextFrame::Deserialize 中的栈缓冲区溢出，由 745 字节的 AddObj 协议数据单元（PDU）触发。在 7.1.5 和 7.0.6 版本之前，所有使用端到端加密设置的 Zoom Workplace 客户端仍然易受攻击，用户应立即更新。</p>
<div class="news-background"><strong>背景</strong> 零点击漏洞利用是一种无需用户交互（如点击链接或打开文件）即可发起的网络攻击，因此尤为危险。协议数据单元（PDU）是网络对等实体间传输的单个信息单元，包含协议特定的控制信息和用户数据。前沿 AI 模型是具有广泛能力的先进人工智能系统，正越来越多地应用于漏洞研究，大幅缩短了开发可用漏洞利用所需的时间和专业技能。</div>

<h2 class="news-title"><a href="https://github.com/xoreaxeaxeax/skitter-creek-bath-salts">DRAM 扰动利用解锁隐藏的 CPU 功能与安全机制</a><span class="score-badge score-high">9.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 13, 16:06</span></div>
<p class="news-summary">Christopher Domas 发布了 skitter-creek-bath-salts 研究工具，利用 DRAM 扰动（scrambling）重映射物理内存地址。在 AMD Family 16h CPU 上，它暴露受保护的 DRAM 区域，并解锁 Platform Security Processor (PSP)、System Management Mode (SMM)、C6 DRAM 和 CPU 微码。 这项研究表明，建立在 DRAM 地址翻译之上的硬件级安全原语可能通过重新配置内存控制器而被打破，从而使 SMM、微码和 PSP 等通常对内核也不可见的保护措施失效。底层地址翻译变换同样适用于 ARM 和 RISC-V 等其他架构，这可能构成一类广泛存在的漏洞。 该工具在 AMD Family 16h CPU 上开发和测试，这是最后一代数据手册公开了 DRAM 控制器翻译寄存器且这些寄存器无法锁定的产品。它包含一个 DRAM 状态分析流水线（gather_aliases.py / unspaghettify.py），并将于 Black Hat 2026 上以题为 “Spaghettifying DRAM” 的演讲进行展示。</p>
<div class="news-background"><strong>背景</strong> DRAM 扰动（scrambling）是内存控制器在数据到达 DRAM 之前重新排列地址位的一种技术，主要目的是降低数据总线上的电流波动和电磁干扰。当程序解引用指针时，虚拟地址要经过一个很长的流水线：MMU 翻译，然后由内存控制器进行 channel、rank、bank 交织和 swizzle，最后才访问到具体的 DRAM 位置。AMD PSP、Intel ME、SMM 以及内存 carveout 等安全机制都依赖于这些地址翻译的保密性；如果攻击者能够重新配置 DRAM 控制器的翻译寄存器，就能访问到那些被隐藏的内存区域。</div>

<p class="news-summary">安全公司 CloudSEK 和 Hudson Rock 披露，针对开源 AI 工具 LiteLLM 的供应链攻击泄露了来自大型组织的数 TB 凭据。凭据是在 3 月的一个 40 分钟窗口内，从从 PyPI 下载的受损 LiteLLM 版本中窃取的，受害者包括 Microsoft、Amazon、Cisco、Samsung 和 Salesforce。 这一事件之所以重大，是因为它攻击了一款广泛使用的开源 AI 工具，并暴露了全球最大组织中部分敏感访问密钥，可能使攻击者能够入侵超过 2,500 家组织。它突显出糟糕的 AI 和 DevOps 安全会如何让企业即使面对松散的小型威胁组织也毫无防备。 泄露的凭据包括云密钥、仓库令牌、SSH 密钥、Kubernetes 密钥、软件包发布凭据、环境变量和 AI 提供商密钥。LiteLLM 遭入侵可追溯到此前的供应链攻击，该攻击感染了 Trivy 漏洞扫描器、KICS 和 Telnyx Python SDK；以青少年为主的团队 TeamPCP 声称对此负责。</p>

<h2 class="news-title"><a href="https://github.com/openai/openai-python/releases/tag/v3.0.0">OpenAI Python SDK v3.0.0 将默认 HTTP 客户端切换为 HTTPX2</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-github">github</span><span class="source-name">openai-sdks[bot]</span><span class="news-time">Aug 12, 01:54</span></div>
<p class="news-summary">OpenAI 于 2026 年 8 月 12 日发布 openai-python v3.0.0，将 HTTPX2 设为默认 HTTP 客户端，并取消自动安装 httpx。使用自定义 HTTPX 客户端、传输层或配置对象的应用必须迁移到 HTTPX2 等价物，或使用临时的旧版兼容逃生通道。 这是广泛使用的 OpenAI Python SDK 多年来的首个主版本，引入了影响众多自定义 HTTP 层开发者的破坏性变更。转向 HTTPX2 使 SDK 与下一代 Python HTTP 客户端保持一致，开发者需要规划迁移。 破坏性变更归类在 api scope 下，发布说明中附有专门的 HTTPX2 迁移指南。httpx 不再自动安装，依赖它的用户需要将 httpx 或 httpx2 包显式加入依赖。</p>
<div class="news-background"><strong>背景</strong> HTTPX 是 Python 3 功能齐全的 HTTP 客户端，提供同步与异步 API，支持 HTTP/1.1 和 HTTP/2。HTTPX2 是其继任版本，生态中的项目正从原版 httpx 迁往 httpx2。OpenAI Python SDK 此前在底层使用 httpx 发送所有 OpenAI API 请求。</div>

<h2 class="news-title"><a href="https://mcfunley.com/choose-boring-technology">《选择无聊的技术》：用固定创新代币管理技术风险</a><span class="score-badge score-mid">8.0</span></h2>

<p class="news-summary">在 2015 年的文章中，Dan McKinley 提出工程团队应有意识地限制采用有风险的新技术数量，并引入“创新代币”（innovation token）概念。他认为每家公司大约只有三个创新代币，应慎重花在真正需要创新的少数领域。 这篇文章已成为软件工程文化与技术战略领域的经典参考，常被引用来支持保守的技术选型。“创新代币”的框架帮助工程师和领导者清晰解释取舍，降低组织风险。 在文章的框架中，对公司或行业而言较新的技术会消耗一个创新代币，例如采用新的数据库就花掉一个。值得注意的是，“无聊”技术并不意味着过时或较差，而是指经过验证、团队熟悉、能减少运维意外的工具。</p>

<p class="news-summary">研究人员演示了如何将 Anthropic、OpenAI 和 Google 的 LLM API 返回的加密思维链数据块在会话和用户之间重放，再在较弱的模型中越狱，从而以明文恢复隐藏的推理内容。这一被描述在“Stolen Thoughts”论文中的攻击已被所有提供商确认并修复。 这之所以重要，是因为攻击绕过了防蒸馏机制，暴露了专有模型的私有推理过程，削弱了这些模型在竞争力和安全性上所依赖的保密性。它还揭示了一个系统性缺陷：加密推理块在同一模型家族中共享密钥，从而为新的提示注入和数据外泄攻击打开了大门。 研究人员发现，同一模型家族中的所有模型都使用相同的加密密钥，因此可以将前沿模型的加密块输入较弱的同族模型（如 Claude Haiku 4.5），通过越狱让它输出原始推理内容。他们还描述了一种提示注入变体：诱使模型在思考轨迹中规划数据外泄，然后将该轨迹喂给另一模型以影响其行为。</p>
<div class="news-background"><strong>背景</strong> 思维链（chain-of-thought, CoT）是 LLM 在解题时逐步进行的内部推理过程，提供商通常对用户保密，以防止蒸馏和滥用。然而，API 有时会将加密的 CoT 副本返回给客户端，客户端在后续请求中再将其发送给模型，以保持上下文。重放攻击（replay attack）是指重复发送有效数据来欺骗系统；在这项研究中，研究人员将加密块重放给不同的模型。“Stolen Thoughts”论文（arXiv 2608.09867）及网站 stolen-thoughts.com 披露了这一攻击，并展示了示例轨迹。</div>
