<h2 class="news-title"><a href="https://simonwillison.net/2026/Sep/8/on-navier-stokes/">OpenAI 声称用 AI 破解纳维-斯托克斯千禧年问题</a><span class="score-badge score-high">10.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Simon Willison</span><span class="news-time">Sep 8, 23:55</span></div>
<p class="news-summary">2026 年 9 月 8 日，OpenAI 宣布其一个未发布的内部模型运行约 10,000 个 AI 智能体，对纳维-斯托克斯存在性与光滑性问题提出了一个解析方案，并已在 Lean 证明助手中完成形式化。该结果尚未经外部数学家验证，OpenAI 表示不会因此申领 100 万美元的千禧年奖。 如果得到验证，这将是首个在 AI 大量协助下解决的千禧年问题，可能标志着数学研究方式的范式转变。它还引发了关于研究优先权、训练数据污染，以及数学界能否信任大规模 AI 系统所生成证明的紧迫问题。 该公告伴随一场优先权争议：纽约大学教授 Tristan Buckmaster 与 Anthropic 数学家 Levent Alpöge 表示，他们经过近一年、借助 Claude 和 Codex 的研究后于 8 月 15 日取得相关突破，并指控 OpenAI 是在听到他们成果的传闻后才开始行动的。OpenAI 则称其项目始于 9 月 1 日，且在该成果公开发布前未以任何方式看到对方的成果；所有被尝试的问题中，智能体共发送 490 万条消息，消耗约 3000 亿个输出 token。</p>
<div class="news-background"><strong>背景</strong> 纳维-斯托克斯存在性与光滑性问题探讨的是：描述流体运动的偏微分方程在三维空间中，给定初始速度场后，是否总存在光滑且全局定义的解，还是解可能会在有限时间内破裂。这是克莱数学研究所在 2000 年设立的七个千禧年问题之一，每个问题悬赏 100 万美元；截至 2026 年，仅庞加莱猜想得到官方确认并颁奖。千禧年问题的解答必须经过数学界评审并被接受，OpenAI 的公告也明确指出其成果尚未得到验证。</div>

<p class="news-summary">据 Tailwind CSS 博客公告，Shopify 已收购开源 utility-first CSS 框架 Tailwind CSS 背后的公司 Tailwind Labs。此次收购引发了人们对这一广泛使用的框架长期发展方向和独立性的疑问。 Tailwind CSS 是现代 Web 开发中使用最广泛的 CSS 框架之一，因此被大型电商平台收购可能会重塑该开源项目的治理和资金模式。此次收购也凸显了 AI 代码生成工具对 Tailwind Labs 等开发者工具公司商业模式的冲击。 在早前的社区讨论中，Tailwind 联合创始人 Adam Wathan 指出，AI 已严重冲击公司业务，包括自 2023 年初以来文档流量下降约 40%，以及约 75% 的工程团队成员被裁员。此次收购发生在 UI 模板等相关产品市场因 AI 生成代码而面临越来越大压力的背景之下。</p>

<h2 class="news-title"><a href="https://spectrum.ieee.org/are-self-driving-cars-safe">更多证据表明自动驾驶汽车能挽救生命</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-hackernews">hackernews</span><span class="source-name">bookofjoe</span><span class="news-time">Sep 9, 17:14</span></div>
<p class="news-summary">《IEEE Spectrum》的一篇文章指出，越来越多证据表明自动驾驶汽车能减少碰撞并挽救生命。讨论重点之一是 Waymo 等公司如何展示其安全记录。 如果这些证据成立，自动驾驶汽车将深刻影响道路安全、保险和交通政策。比较基准的选择——是普通驾驶员、网约车驾驶员还是公共交通——也会直接改变这项技术看起来是否成功。 评论者提出了方法上的注意事项：Waymo 是用自己的事故率与“普通驾驶员”而非其无人驾驶出租车所替代的网约车驾驶员进行比较；全国死亡数据也会受到安全带使用、超速、酒驾以及行人和骑车人死亡的影响。保险成本变化和公共交通投资也被视为重要的比较维度与社会后果。</p>
<div class="news-background"><strong>背景</strong> 自动驾驶汽车依靠传感器、摄像头和人工智能在有限人工干预下行驶，Waymo 等公司已将其投入商业 Robotaxi 运营。要证明它比人类驾驶员更安全并不容易，因为自动驾驶车队只在特定城市和条件下运行，选择什么样的人类基线会显著影响结论。理解这些基线，是评估“自动驾驶能以规模挽救生命”这一说法的前提。</div>

<h2 class="news-title"><a href="https://magazine.sebastianraschka.com/p/gpt-6-astra-looped-transformers-and">GPT-6 Astra 分析：循环 Transformer 与隐藏推理</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Ahead of AI (Sebastian Raschka)</span><span class="news-time">Sep 9, 11:14</span></div>
<p class="news-summary">Sebastian Raschka 发布了对 OpenAI GPT-6 Astra 的深入分析，剖析了其传闻中的循环 Transformer 架构、循环深度，以及该模型可能隐藏思维链推理过程的猜测。 由于 GPT-6 Astra 是标志性模型并代表了当前的 AI 性能标杆，弄清它是否采用循环或递归计算以及隐藏推理，有助于理解 LLM 架构与可解释性的发展方向。这也将产品实际体验与 mixture-of-depths 和思维链等学术研究联系起来。 Raschka 解释说，循环 Transformer 会复用一组共享层，由学习到的 router 决定每个 token 经过多少次迭代，即 Mixture-of-Recursion 方法，并比较了 expert-choice 与 token-choice 两种路由方式。他还讨论了这种循环在技术上是否与“隐藏”思维链有关，并指出 Astra 在 3D 渲染和动画任务上表现格外突出。</p>
<div class="news-background"><strong>背景</strong> 思维链提示（chain-of-thought prompting）由 Wei 等人于 2022 年提出，通过让大语言模型在给出最终答案前生成中间推步骤，来改善复杂推理能力。循环（或递归）Transformer 可追溯至 Universal Transformer 等思路，它反复应用同一组层来增加有效深度，而无需新增参数。GPT-6 Astra 及其架构的技术细节目前仍主要基于分析和猜测，而非官方文档。</div>

<p class="news-summary">这篇技术文章认为，像 Go 的 context.Context 这样的函数参数并不是“函数颜色”，尽管编程语言讨论中有人持相反主张。文章提出一条判断标准：真正的颜色会迫使改动沿调用栈传播到所有中间函数，而普通参数通常可以在中间层次被封装起来，不必一路传到调用栈顶端。 这一区分对编程语言设计和 API 易用性很重要，因为它决定一种特性是否会“污染”整个调用栈。通过说明类似 context 的参数并不是颜色，文章厘清了显式参数与 async、STM 这类隐式控制流效应之间的边界。 文章将颜色定义为一种越过中间调用、直接要求调用栈中相关“颜色岛”内所有栈帧都满足的改动；如果中间某个函数原则上能把要求封装起来、使上层函数不受影响，那么这种改动就不是颜色。文章还指出，大多数语言不允许用户自行定义新颜色，而且 async 也并非在所有语言中都必然是颜色。</p>
<div class="news-background"><strong>背景</strong> “函数颜色”这一概念源于关于 async/await 的讨论：在许多语言中，异步函数不能直接从同步函数调用，因此一旦某个函数变成 async，它的调用方也往往需要相应改动。文章以 Go 的 context.Context 为例，这是一种专为在函数调用间携带超时、取消信号和少量请求级数据而设计、需要逐层传递的值，表面上看很像是颜色。论述“函数颜色”的原始文章正是以 async 作为无法在调用栈中途封装、只能一路向上传播的典型例子。</div>
