<h2 class="news-title"><a href="https://openai.com/index/ten-advances-in-mathematics/">OpenAI 盘点数学与理论计算机科学十大进展</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-hackernews">hackernews</span><span class="source-name">milkshakes</span><span class="news-time">Aug 3, 16:27</span></div>
<p class="news-summary">OpenAI 发布了一篇博文，重点介绍了人工智能模型在数学和理论计算机科学领域帮助解决或推进问题的十项最新进展。文中涵盖多个领域，包括高维球堆积和多色拉姆齐数，读者也特别提到了这些内容。 这一进展意义重大，因为它表明 AI 模型正成为纯数学领域的有用工具，而这一领域传统上被认为需要人类的直觉。这篇文章可能会鼓励更多研究者将 AI 用于猜想生成、证明搜索和形式化验证，从而重塑数学发现的方式。 这篇博文是对十项独立进展的总结，而非单一的新突破，且未提供每项成果的完整技术细节。一些评论者担心其表述可能为营销而夸大，因此需要仔细审视。</p>
<div class="news-background"><strong>背景</strong> 自动定理证明（ATP）是计算机科学与数理逻辑的一个子领域，旨在通过计算机程序证明数学定理。证明助手（proof assistant）又称交互式定理证明器，允许人机协作构建形式化证明。近来，研究者开始利用 AI 生成猜想并自动化形式化的部分环节。OpenAI 的这篇博文正是这一趋势的一部分，展示了 AI 如何帮助数学家完成诸如反驳猜想和构建形式化论证等任务。</div>

<h2 class="news-title"><a href="https://blog.comfy.org/p/minimax-h3-day-0-support-in-comfyui">MiniMax H3 获 ComfyUI Day-0 支持：开放权重与 2K 视频</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-hackernews">hackernews</span><span class="source-name">vblanco</span><span class="news-time">Aug 3, 13:34</span></div>
<p class="news-summary">MiniMax H3 作为开放权重的通用多模态视频模型，现已获得 ComfyUI 的 Day-0 支持，可生成最长 15 秒、带原生立体声的 2K 视频。本次发布还引入了一项新颖的剪枝技术，将内存占用降低 66%，使模型能在消费级 GPU 上本地运行。 这标志着开放权重视频生成迈出重要一步，将具备原生音频的顶尖视频能力带到本地消费级硬件上，而此前这类任务需要大型服务器集群。这可能大幅加速艺术家、开发者和小型工作室对 AI 视频的采用。 该剪枝技术将模型的调制权重（约占全部参数的 40%）替换为功能等效的查找表，使最小变体的内存占用从全精度的 123.6 GB 降至 42.5 GB，并结合动态 VRAM 卸载可在 RTX 3060 上运行。社区反馈显示，16 GB 的 RTX 4070 Ti Super 生成一段 10 秒 480p 视频约需 10 分钟。</p>
<div class="news-background"><strong>背景</strong> MiniMax H3 是一个开放权重的通用多模态模型，可将文本、图像、视频和音频作为统一上下文读取，并生成最长 15 秒、最高 2K 分辨率、24fps、带原生立体声的视频片段。ComfyUI 是一款流行的基于节点、开源且主要在本地运行的生成模型图形界面。模型剪枝是一种移除神经网络中不重要参数的技术，旨在减小模型规模与计算负担，同时尽量保持输出质量。</div>

<p class="news-summary">Jane Street 发布了 Bonsai，这是一个使用 Js_of_ocaml 在 OCaml 中构建反应式网页应用的库，该公司大部分内部网页应用都由它驱动。该发布还包括用于浏览器界面的 Bonsai_web 和用于终端界面的 Bonsai_term。 Bonsai 让 OCaml 开发者可以在前端和后端使用相同的语言和类型，从而减少大型网页应用代码库中的错误。其增量渲染和可组合状态机为以 OCaml 为中心的团队提供了 JavaScript 框架之外的有力替代方案。 Bonsai 组件是纯函数式状态机，仅在相关状态变化时进行增量渲染。它包含模板语言、组件级样式表以及整套应用的自动化测试系统；核心 Bonsai 库是通用的，Bonsai_web 和 Bonsai_term 是专用的上层。</p>

<h2 class="news-title"><a href="https://research.jfrog.com/post/sqlite-critical-cves-or-llm-slops/">JFrog：SQLite“严重”CVE 实为 LLM 生成的垃圾信息</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 3, 16:51</span></div>
<p class="news-summary">JFrog 安全研究人员发现，由一个新建 GitHub 仓库（programmervuln/cveadvisory-）发布的一批 SQLite CVE 很可能是 LLM 生成的垃圾信息，其中引用了不存在的代码、PoC 无法生效，并且这些 CVE 未出现在 SQLite 官方公告页面上。NVD 和 CISA 的 ADP 最初将其中几个标记为严重，而 Red Hat 此后已将 CVE-2026-51302 的评分从 10.0 严重下调至 7.6 高危。 这一事件表明，AI 生成的漏洞报告可能污染权威 CVE 数据库，产生虚假的严重告警，浪费安全团队的时间，并导致自动化工具去修补或分析根本不存在的代码。它凸显了随着 LLM 输出越来越多地进入安全生态系统，验证和人工监督的必要性日益增强。 JFrog 的审计发现，引用的 SQLite expr.c 行号要么是注释，要么是不相关的内存分配调用，PoC 载荷执行时未发生崩溃或内存错误。报告还引用了目标版本 SQLite 3.41.0 中不存在的函数（如 jsonBlobEdit()），并且将这些公告合并处理后触发了 GPTZero 的 AI 生成内容警告。JFrog 已正式向 GHSA、Red Hat 和 NVD 报告了这些发现。</p>
<div class="news-background"><strong>背景</strong> CVE 记录由 NVD 进行丰富，而近年来 CISA 通过其授权数据发布者（ADP）角色和 Vulnrichment 项目为漏洞条目补充 CVSS 与 CWE 数据。GitHub 咨询数据库（GHSA）是另一个主要的安全公告来源，通常包含描述、严重性、受影响版本和补丁信息。“LLM 垃圾信息”指的是大型语言模型生成的低质量、常包含幻觉的内容，这类内容看似合理但缺乏事实依据。</div>

<h2 class="news-title"><a href="https://www.theverge.com/ai-artificial-intelligence/974571/eu-ai-act-transparency-labels-rules-deepfakes">欧盟人工智能法案透明度规则 8 月 2 日生效</a><span class="score-badge score-mid">8.0</span></h2>

<p class="news-summary">Rust 项目已接受一项 2026–2027 年目标，拟引入 Move 和 Forget trait，让类型可以选择不被移动或不被遗忘。该提案旨在实现安全的 scoped spawn、async drop 以及默认 pin 行为。 这将把不可移动性等关键机制从基于位置的 Pin 转移到类型级保证，从而简化自引用类型和异步代码。它还可能首次让 scoped 并发等模式在稳定 Rust 中变得安全，并惠及 Linux 内核等重要用户。 该计划包括编译器 MVP、针对 Move 的 RFC，以及在 Linux 内核中的实际测试，由 @lcnr 和 @jackh726 负责推进。!Forget 实现将保证析构函数一定会运行，从而支持安全的 scoped spawn；团队还指出 Move 不应是 Destruct 的 supertrait。</p>

<p class="news-summary">这篇文章分析了 Zig 考虑采用类似 Fil-C 的编译目标的方案，该方案号称真正内存安全，与 Rust 的 unsafe 逃生舱门形成对比。文章指出，Fil-C 对内存安全的定义与 Rust 不同，因此两种方法不能直接相提并论。 这件事很重要，因为内存安全仍然是 C/C++ 系统编程面临的关键挑战，而这一比较可能会影响语言如何在安全、实用性和兼容性之间取得平衡。它会影响语言设计者、C/C++ 开发者以及整个迈向内存安全软件的趋势。 Fil-C 通过基于能力的指针和动态检查，为未经修改的 C/C++ 代码提供内存安全；而 Rust 则依赖静态类型系统和显式的 unsafe 块。文章提出，实用的内存安全边界应当在安全一侧拥有简单、易于遵循的规则，并将显式的 FFI/unsafe 构造类比为清晰的“一切皆可发生”的指示。</p>

<h2 class="news-title"><a href="https://blogs.gnome.org/feborges/future-of-boxes/">GNOME Boxes 从零重建，新增 Windows 11 支持</a><span class="score-badge score-mid">7.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 3, 17:16</span></div>
<p class="news-summary">经过两年开发，GNOME Boxes 已从头重写，改为仅通过 Flatpak 分发，并迁移到 GTK4/Libadwaita。新版本会自动配置 Secure Boot 和虚拟 TPM，让 Windows 11 无需手动绕过即可通过硬件兼容性检查。 这解决了经典版 Boxes 中最受期待的功能——无缝支持 Windows 11——并让该应用在不可变的、基于镜像的 Linux 发行版上更具可行性。通过将整个虚拟化栈打包进 Flatpak，Boxes 能在不同发行版上提供受控且一致的后端，有利于希望快速创建虚拟机的 Linux 桌面用户。 新版本仅通过 Flatpak 分发，已迁移到 GTK4/Libadwaita，并用 Libmks 取代了基于 GTK3 的 SPICE 显示组件。它支持从 ISO 和 qcow2 镜像创建虚拟机、配置资源、剪贴板共享、文件传输和端口转发，但目前仍是 Beta 版，不建议用于生产环境。</p>
<div class="news-background"><strong>背景</strong> GNOME Boxes 是一款 Linux 桌面应用，作为 libvirt/QEMU 的前端，用于创建和管理虚拟机。TPM（Trusted Platform Module）是一种安全协处理器，用于验证启动过程是否从可信状态开始；Windows 11 要求 TPM 2.0 和 Secure Boot，而虚拟 TPM 设备可在虚拟机内模拟该硬件。qcow2 是 QEMU 的一种磁盘镜像格式，采用写时复制和延迟存储分配策略。</div>
