## [DeepSeek-V4 发布：专为 AI Agent 优化的百万 Token 上下文窗口](https://huggingface.co/blog/deepseekv4) ⭐️ 9.0/10

DeepSeek 正式发布了 DeepSeek-V4 模型，该模型采用 1T 参数的 MoE 架构，内置一百万 Token 的上下文窗口，并专门针对长周期 AI Agent 工作流进行了优化。 该发布解决了当前 AI 系统中的一个关键瓶颈，将长上下文从理论极限转化为复杂多步 Agent 任务中真正可用的记忆能力。这标志着 LLM 生态系统正朝着优先考虑上下文保持可靠性和工具调用稳定性的架构方向发生重大转变。 该模型采用结合压缩稀疏注意力与重度压缩注意力的混合注意力架构以维持大规模下的效率，而其基础版本采用纯 FP8 混合精度，不适用于直接的对话或工具调用。开发者在将其集成到生产级 Agent 框架时，必须充分考虑这些架构限制。

rss · Hugging Face Blog · Apr 24, 00:00

**背景**: 大语言模型以离散的 Token 为单位处理文本，上下文窗口决定了模型在生成过程中能够同时处理的 Token 数量。尽管近期模型已将上下文窗口扩展至百万级别，但单纯扩大窗口往往会导致注意力分散、延迟增加以及信息检索不可靠。长时间运行的 AI Agent 需要在交互过程中保持稳定的记忆，而传统的上下文扩展技术若不经过专门的架构优化，很难满足这一需求。

## [Qt 强制信号槽连接使用上下文对象](https://blog.broulik.de/2026/04/qt-no-contextless-connect/) ⭐️ 7.0/10

从 Qt 6.7 开始，开发者可以定义 QT_NO_CONTEXTLESS_CONNECT 宏，强制所有信号与槽的连接必须显式指定上下文对象，从而移除了框架以往默认的无上下文连接行为。 这一改动通过防止接收对象销毁时悬空指针导致的崩溃，显著提升了应用程序的稳定性和线程安全性。同时，它促使 C++/Qt 开发者采用更明确的对象所有权模型和更清晰的 API 设计。 无上下文连接过去默认采用 Qt::DirectConnection 类型，会直接在发送者线程中立即执行槽函数，忽略线程亲和性。指定上下文对象后，Qt 会在该对象销毁时自动断开连接，从而免去了手动清理的麻烦并降低了竞态条件风险。

rss · Lobsters · Apr 24, 17:42

**背景**: Qt 的信号与槽机制是对象间通信的核心功能，通常与 Lambda 表达式或标准 C++ 函数结合使用。在连接到非 QObject 目标时，开发者可选择传入一个上下文对象来管理连接的生命周期。如果上下文对象被销毁，Qt 会自动断开该信号连接，从而避免调用无效内存。若不使用上下文，连接将一直存在直至手动断开或发送者销毁，这在多线程或动态管理的应用中容易引发隐蔽的缺陷。
