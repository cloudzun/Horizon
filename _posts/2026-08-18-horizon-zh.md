<h2 class="news-title"><a href="https://simonwillison.net/2026/Aug/17/qwen-38-27b-scores-52/">Qwen 3.8 27B 智能指数得分 52，匹敌远大规模模型</a><span class="score-badge score-high">9.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Simon Willison</span><span class="news-time">Aug 17, 23:58</span></div>
<p class="news-summary">Qwen 3.8 27B 在 Artificial Analysis Intelligence Index 上获得 52 分，与 GPT-5.6 Luna（max）持平，仅比 753B 的 GLM-5.2 和 1.7T 的 DeepSeek V4 Pro 低 1 分。这个 27B 参数的模型匹敌或接近了规模大数个数量级的模型。 这是一次重大的效率突破，表明模型规模不再是达到前沿智能的唯一途径。一个 27B 模型能匹敌规模大数百至数千倍的模型，可能重塑部署成本结构，并让强大 AI 在单张 GPU 上运行成为现实。 Qwen 3.8 27B 是一个原生视觉语言模型，支持灵活思考控制，在 Hugging Face 上提供 FP8 和全精度版本。据 Yotta Labs 介绍，这个 27B 稠密模型在 BF16 下大约需要 56GB 显存，FP8 下约 28GB，4-bit 下约 14-16GB（均不含 KV cache）。</p>
<div class="news-background"><strong>背景</strong> Artificial Analysis Intelligence Index 是一个综合性的模型“智能”指标，融合了智能体能力、长上下文推理和特定场景评估。当前版本 v4.1.1 结合了九项评估，包括 GDPval-AA v2、Humanity&#x27;s Last Exam、GPQA Diamond 和 AA-Omniscience。该对比之所以引人注目，是因为 GPT-5.6 Luna 的规模可能远大于 27B，而 GLM-5.2 为 753B 参数，DeepSeek V4 Pro 为 1.7T 参数。</div>

<h2 class="news-title"><a href="https://www.modular.com/blog/mojo-open-source">Mojo 编译器在 Apache 2.0 下全面开源</a><span class="score-badge score-high">9.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 18, 16:34</span></div>
<p class="news-summary">Modular 宣布 Mojo 编程语言现已在 Apache 2.0 许可证（含 LLVM 例外）下全面开源。Mojo 编译器、标准库和工具链的源代码现已发布在 Modular 的 GitHub 仓库中，并附有从源码编译的说明。 Mojo 专为 AI 和高性能加速计算而设计，其编译器全面开源消除了采用过程中的一大障碍。开发者现在可以完全查看和控制语言工具链，这使 Mojo 成为 AI 基础设施等领域更值得信赖的开源替代方案。 该项目位于 Modular 的 GitHub 仓库中，可通过单条 Bazel 命令构建编译器，例如 &#x27;./bazelw run --config=build-mojo KGEN:mojo -- run hello.mojo&#x27;。标准库自 2024 年起已接受贡献，但 Modular 表示尚未准备好接受编译器和工具链的贡献，计划在今年年底前开放。</p>
<div class="news-background"><strong>背景</strong> Mojo 是 Modular 公司开发的一款系统编程语言，融合了受 Rust 启发的静态类型和借用检查机制，同时采用类似 Python 的语法；它构建在 MLIR 编译器框架之上，而非直接基于 LLVM。这种设计使 Mojo 能够面向 CPU、GPU、TPU 及其他加速器生成代码，特别适合 AI 工作负载。该语言于 2026 年 8 月发布 1.0 版本，此次公告标志着其从&#x27;开放社区但封闭编译器&#x27;转变为完全开源项目的重要里程碑。</div>

<h2 class="news-title"><a href="https://portswigger.net/research/css-the-bomb-inside-your-inbox">CSS 清理绕过可窃取 Webmail 令牌与密码</a><span class="score-badge score-high">9.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 18, 13:30</span></div>
<p class="news-summary">PortSwigger 研究员 Gareth Heyes 于 2026 年 8 月 6 日发布研究，详细展示了针对 Yahoo Mail、AOL Mail、Fastmail、ProtonMail、Gmail 和 Outlook 等 Webmail 客户的 CSS 清理绕过技术。这些技术可以突破信任边界、窃取 Slack token 等敏感数据、入侵第三方网站，甚至窃取密码。 这项研究表明，CSS 清理并非可靠的安全边界，所展示的攻击会影响广泛使用的 Webmail 服务，并可能窃取凭据和令牌。随着 Webmail 越来越多地集成 AI 代理，该研究也揭示了一个不断扩大的攻击面，类似的 CSS 技术可能会被用来攻击这些 AI 相关功能。 该论文介绍了基于 CSSOM 的变异攻击，即浏览器内存中的 CSS 表示形式可以将安全规则转化为恶意规则，还介绍了 image-set() 回退技术，可在清理机制存在的情况下触发外部请求。论文还提出了一种基于点击的泄露技术，适用于 Content Security Policy（CSP）阻止外部资源的情况；完整源代码已在 GitHub 上公开。</p>
<div class="news-background"><strong>背景</strong> Webmail 客户端必须在受信任的界面中显示不受信任的 HTML 和 CSS，因此它们依赖清理器（sanitizer）来白名单化所谓安全的属性。攻击者会寻找清理器认为安全与实际浏览器渲染结果之间的差异。CSS Object Model（CSSOM）尤其值得关注，因为浏览器在读取属性时可能会对属性进行变换，从而将无害的 CSS 变成攻击代码。CSS 还常被滥用于数据泄露，例如通过属性选择器和 image-set() 等函数触发后台请求。</div>

<h2 class="news-title"><a href="https://duckdb.org/2026/08/17/duckdb-20-highlights.html">DuckDB v2.0 预览：服务器模式、触发器、VARIANT 与 40 倍提速</a><span class="score-badge score-high">9.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Lobsters</span><span class="news-time">Aug 17, 16:13</span></div>
<p class="news-summary">DuckDB 发布了 v2.0 预览版，代号“Cyanoptera”，公布了服务器模式、触发器、VARIANT 类型、异步 I/O、新 SQL 解析器、新存储格式以及重做的 C API 等主要特性。预览显示，与 v1.5.4 相比，一个递归查询微基准测试的性能提升了 40 倍。 这是最广泛使用的嵌入式分析数据库之一的一次重大版本发布，标志着其从仅支持进程内运行向支持客户端/服务器部署的战略转变。性能提升和新的 SQL 功能将直接惠及数据工程师与分析工作负载，而新的存储格式和解析器带来的破坏性变更也需要整个生态去适应。 该版本基于 v1.5 以来的 10,000 多次提交构建，v2.0 将包含破坏性变更，例如新的默认存储格式和 lambda 语法过渡的完成。行组裁剪已扩展到涵盖 struct、list、decimal、UUID、IN 过滤器和函数谓词，并且查询规划现在对 lakehouse 格式具有分区感知能力。</p>
<div class="news-background"><strong>背景</strong> DuckDB 是一款进程内分析型 SQL 数据库，专为在应用程序中进行快速分析查询而设计。VARIANT 类型首次在 DuckDB v1.5 中得到支持，为存储和查询 JSON 等半结构化数据提供了一种高性能方式。服务器模式基于 2026 年 5 月公布的 Quack 远程协议，该协议允许 DuckDB 实例通过 HTTP 进行通信。递归 CTE 是用于图遍历和可达性查询的标准 SQL 特性。</div>

<h2 class="news-title"><a href="https://huggingface.co/blog/multi-vector-encoder">Hugging Face 推出用于晚期交互检索的 MultiVectorEncoder</a><span class="score-badge score-mid">8.0</span></h2>
<div class="news-meta"><span class="source-chip chip-rss">rss</span><span class="source-name">Hugging Face Blog</span><span class="news-time">Aug 18, 00:00</span></div>
<p class="news-summary">Hugging Face 发布了 MultiVectorEncoder，这是 Sentence Transformers 中用于 ColBERT 式晚期交互模型的新 API。它可以直接加载 PyLate 和 Stanford-NLP 的 ColBERT 检查点，以及用于视觉文档检索的 colpali-engine 模型，并与 Weaviate 等向量数据库集成。 这一功能简化了晚期交互检索的采用，这类模型保留 token 级匹配信息，通常比单向量嵌入获得更好的检索质量，但需要更大的索引。它还让最先进的视觉文档检索（如 ColPali 风格）能够通过 Sentence Transformers 中与 dense、sparse 和 reranker 模型相同的熟悉 API 使用。 多向量模型为每个 token 保留一个向量，并使用 MaxSim 运算符计算查询与文档的相似度，而不是将整个文本压缩为单个向量。博客演示了包含 4,874 篇文档（608,414 个 token 向量）的语料在 41 秒内导入 Weaviate，查询仅需 17ms 即可返回结果。</p>

<p class="news-summary">Rust Cargo 团队正在 nightly 频道默认启用 -Zembed-metadata=no 特性开展实验，根据不同的 profile，target 目录大小可减少约 5%–30%。用户被要求反馈问题，并可通过 Cargo 参数或配置选择退出。 在 2025 年 Rust 官方调查中，Rust 编译产物的高磁盘占用是仅次于编译速度的第二大常见问题。这项实验若能稳定落地，将为所有 Rust 开发者带来一种低成本缩减 target 目录大小的方法。 缩减幅度取决于 target 目录中 crate 元数据所占比例：基准测试显示默认 dev profile 可减少 4.7%，而在不带 debuginfo 和增量编译的 release profile 下最高可减少 29.8%。用户可通过 -Zembed-metadata=yes、环境变量 CARGO_UNSTABLE_EMBED_METADATA=true，或在 .cargo/config.toml 中设置 [unstable] embed-metadata = true 来退出实验。</p>
<div class="news-background"><strong>背景</strong> Cargo 默认会编译整个 crate 依赖图，而 .rlib 等编译产物中会嵌入 crate 元数据，导致同一份元数据在多个文件中重复存储。不稳定的 -Zembed-metadata=no 标志让 rustc 只在 .rlib 中保存极简的元数据存根（metadata stub），把完整元数据放到单独的 .rmeta 文件中，使产物仍可被作为依赖使用。Cargo 团队在 nightly 上默认开启该特性，是为了在实际使用中收集反馈，再决定是否将其稳定化。</div>
